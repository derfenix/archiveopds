# Поведение в рантайме

## Память и выдача книг (acquisition)

- Индекс OPDS строится из INPX в RAM: массив всех записей и карты по секциям. Объём памяти линейно зависит от числа книг в индексе.
- При скачивании книги (`/opds/acquire/…`) содержимое записи в zip **не держится целиком в RAM**, если распакованный размер больше **8 МиБ**: данные пишутся во **временный файл** в `os.TempDir()` и отдаются через `ReadSeek` (для `Content-Length` и range-запросов). Потолок одного файла — **256 МиБ**; больше — ошибка «book too large».
- Записи до **8 МиБ** читаются в память одним буфером (быстрее, без диска).
- Кэш открытого **`.zip`** (см. ниже) использует краткую блокировку только на `find` + `File.Open`, без удержания её на всё чтение файла, чтобы **несколько** одновременных `acquire` в один том не выстраивались в одну очередь на весь срок передачи. **Учётный lease** снимается, когда внутренний `ReadCloser` тела ответа закрыт; пока HTTP-клиент не дочитал/не закрыл — том считается занятым. Число одновременно открытых томов ограничивается (**`--max-open-zip-volumes`** / **`ARCHIVEOPDS_MAX_OPEN_ZIP_VOLUMES`**, по умолчанию 512; **0** = без лимита): при переполнении вытесняется **неактивный** том (LRU; тома с ожидающей передачей или **взятым** lease не закрываются). Если **все** закэшированные тома заняты, может временно открыться ещё один с предупреждением в логе; строгий **жёсткий** потолок по FD при экстремальном числе одновременно открываемых **разных** томов не гарантируется.

## Поиск

- Поиск по каталогу — **полный проход** по объединённому списку книг с фильтрацией (по сути **O(N)** по числу записей в индексе на запрос). Строка для сопоставления с параметром `q` **предвычисляется при загрузке индекса** (нижний регистр, объединение полей), без повторной сборки на каждую итерацию.
- Для очень больших библиотек при высокой нагрузке имеет смысл ограничивать запросы: **`--rate-limit-rps`** / **`ARCHIVEOPDS_RATE_LIMIT_RPS`**, при необходимости **`--rate-limit-per-ip`** (по умолчанию включён, отдельный bucket на клиентский IP) и за доверенным прокси — **`--rate-limit-trust-forward`** + **`ARCHIVEOPDS_RATE_LIMIT_TRUST_FORWARD`**. Число **разных** per-IP лимитеров по умолчанию ограничено (**`ARCHIVEOPDS_RATE_LIMIT_MAX_TRACKED_IPS`**, в т.ч. 0 = без капа); при переполнении вытесняется **наименее недавно использовавшийся** адрес, а не вся таблица.

## Ленивые аннотации FB2

- Для книг в FB2 полный текст `<annotation>` при необходимости читается из zip при формировании страницы раздела или результатов поиска. Тома **`.zip` кэшируются** по абсолютному пути (см. лимит открытых томов и LRU выше). Кратковременная блокировка — только на поиск записи в каталоге zip и `Open`; **чтение потока** идёт без удержания этой блокировки. Один и тот же `book` ID **досчитывается** через `singleflight`, чтобы схлопнуть параллельные дочитывания.
- Параллельность ограничена флагом **`--annotation-workers`** / **`ARCHIVEOPDS_ANNOTATION_WORKERS`** (по умолчанию 4, минимум 1, максимум 64), чтобы не читать неограниченно много fb2 с диска одновременно.
- Путь к файлу внутри zip, пришедший из индекса, отвергается, если в нём **`..`**, путь **абсолютный** или иначе небезопасный (защита от злоупотреблений).

## Завершение процесса

- Команда **`serve`** обрабатывает **SIGINT** и **SIGTERM**: HTTP-сервер останавливается через `Shutdown` с таймаутом **30 с**; новые запросы не принимаются, активные соединения дорабатываются в пределах таймаута.
- Ошибки CLI печатаются в **stderr** с префиксом `archiveopds:`; код выхода **1** при ошибке.
